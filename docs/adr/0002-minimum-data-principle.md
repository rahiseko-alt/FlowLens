# 業務フローの発見に要らないデータは保存しない（最小データ原則）

FlowLens が知りたいのは「どの作業を、どの順序で、どれだけ繰り返しているか」であり、「何を書いたか」ではない。保存するかどうかは「後段の AI が業務フローを発見するために必要か」で決め、「取得できるから保存する」は禁止とする。操作再生、RPA 録画、従業員監視のどれとも違う製品にするための線引きである。

## 決めたこと

- **永続保存しないもの**: キー入力の本文、入力欄の Value、メール・チャット・文書・Web ページの本文、Clipboard の本文、パスワード、API Key、Access Token、Cookie、Session ID、スクリーンショット、OCR の全文、UIA Tree から取った大量の画面テキスト。
- **UI Automation**: 残す。保存するのは Control Metadata、操作の種類、ウィンドウ、プロセス、時刻。UI 部品の Name は、固定の UI ラベルとユーザーが書いた内容を確実に見分けられる場合に限って保存する。見分けられなければ、MVP では保存しない側に倒す。
- **キーボード**: hook 自体は使ってよい。保存するのは Operation Type（Ctrl+C / X / V、Enter、Tab、Escape、ショートカットの起動）と、Typing Activity の回数・継続時間だけ。文字、文章、IME の確定内容は保存禁止。Enter を押した時点で入力欄の値を読み取る処理は持たない。
- **Clipboard**: Clipboard Transfer（時刻、copy / cut / paste、元のアプリ、先のアプリ、種類、長さ）だけを持つ。Paste を検出できない場合は、Ctrl+V などの Operation Type で補う。
- **スクリーンショット**: MVP では、初期設定で OFF にするのではなく撮影する処理そのものを持たない。撮影なしで業務フローを発見できるかを先に確かめ、必要だと実データで分かったときだけ追加する。
- **ブラウザ**: ドメインを基本とし、必要なときだけパスまで残す。クエリ文字列、フラグメント、トークン、セッション情報は保存しない。
- **ウィンドウタイトルとファイルパス**: 顧客名や案件名が入りうるので、生の文字列をそのまま保存する設計にしない。正規化、マスク、ハッシュ化、拡張子やファイル名だけを残す、といった粒度を検証してから決める。生の文字列を残す方式を作る場合も、任意選択とする。
- **書き出し時にもう一度無害化する**: 除外アプリの記録の除去、URL の無害化、不要な項目の削除を、保存時に加えて Diagnostic Export の作成時にも行う。

## Consequences

- DeskMate の `input_hooks.py` と `clipboard.py` を直すだけでは、この原則は満たせない。`uia_tree.py` が取っている Name / Value / 構造化テキストや、それを保存しているテーブルも見直す対象になる。
- ウィンドウタイトルの粒度は、業務フローを見分けられる精度とプライバシーの兼ね合いであり、実データで検証する課題として残る。
