# 入れた直後に、Windows が既に残している過去30日分の足跡を読み込む

Collector は、これから先を記録する機能（Live Capture）に加えて、インストール直後に Windows や各アプリが既に残している過去30日分の記録を読み込む機能（Past Import）を持つ。数日で最初の提案ができること（「過去30日の履歴を読んで3日後にご提案します」）は、事業上の大きな価値になるため MVP に含める。読める範囲はできるだけ広く取り、読み込む元ごとに社員が選べるようにする。

## 決めたこと

- **最小データ原則（ADR 0002）はそのまま適用する。** 過去分でも、本文・入力内容・URL のクエリなどは読み込まない。ウィンドウタイトルやファイル名は ADR 0003 と同じく読めない記号と拡張子にする。ブラウザの閲覧履歴はドメインだけにする。
- **読み込む元ごとに選べる。** 初回の説明画面で、読み込む元の一覧と、それぞれから何を読むかを示し、社員が元ごとに外せるようにする。初期状態はすべて選択。同意する前には何も読まない。
- **過去分と記録分は区別して保存する。** 過去分は粒度が粗い（ボタンの種類やコピーの流れは分からない）ので、どちらから来たデータかを必ず残す。Analyst 側で混ぜて数えないため。
- **読み込みはやり直せる。** 初回に外した元を後から追加で読み込めるようにする（読める期間は、その時点から遡れる範囲まで）。

## 読み込む元の候補（実機調査済み: Windows 11 Build 26200）

| 元 | 読めた項目 | 遡れた期間 | 管理者権限 | 実機確認結果 (Windows 11) |
| --- | --- | --- | --- | --- |
| イベントログ（システム） | 起動・終了・スリープ・復帰の時刻 | 約3〜4ヶ月（39,000件超） | 不要 | 成功（一般ユーザー権限で全件読み取り可能） |
| イベントログ（セキュリティ） | ログオン・ロック・解除の時刻 | - | 必要 | 一般ユーザーでは失敗（WinError 1314: 要求された特権なし） |
| SRUM（システムの資源利用記録） | アプリごと・1時間ごとの使用時間 | - | 必要 | 一般ユーザーでは失敗（WinError 5: アクセス拒否） |
| UserAssist（レジストリ） | アプリごとの起動回数・最終使用時刻・合計時間 | 全期間（215件確認） | 不要 | 成功（HKCUからROT13復号して全件取得可能） |
| 最近使ったファイル・ジャンプリスト | 開いたファイル名・拡張子・更新時刻 | 約10ヶ月（677件確認） | 不要 | 成功（%APPDATA%\Recent の .lnk から取得可能） |
| Office の最近使ったファイル | Office で開いたファイルと時刻 | 全期間 | 不要 | 成功（HKCU\Software\Microsoft\Office から取得可能） |
| Chrome / Edge の閲覧履歴 | 訪れたドメインと時刻 | 約3〜10ヶ月（7,000〜10,000件超） | 不要 | 成功（一時コピーによりSQLiteからドメイン抽出可能） |

### 実装で決めたこと（2026-09-27）

- **SRUM は読まない。** 管理者権限が要り、読むには専用のデータベース形式（ESE）を解く部品が必要で、依存を増やさない方針（`GEMINI.md`）に反するため。社員本人の権限で入れる前提では、どのみち読めない。
- **セキュリティの記録は、ロック・解除・サインアウトだけを読む。** ログオン（4624）はサービスの自動ログオンが大量に混ざり、見分けるには利用者名を含む項目を読む必要があるため。管理者権限が無いと失敗し、その旨が読み込み結果に残る。
- **アプリの利用回数（UserAssist）は、実行ファイル（.exe）の項目だけを読む。** 文書やショートカットの項目は名前が何でもありうるため。値は「PC に入ってからの累計」であり、30日分ではない。セッションのように見せかけず、累計として保存する。
- **最近使ったファイルは Recent フォルダのショートカットから読む。** ジャンプリストは読まない。
- **Office の記録で時刻が無い項目は読まない。** 読み込んだ時刻で代用すると、存在しない利用を作ってしまうため。
- **閲覧履歴は訪問ごとの記録（visits）から、ホスト名だけを SQLite の中で切り出して読む。** URL の続きは Python 側に渡らない。

## Considered Options

- 過去分を読まない（記録分だけ）: 安全で単純だが、最初の提案まで約30日かかる。
- 中身を含まない足跡だけに絞る: 閲覧履歴を外す案。事業上の価値を優先し、元ごとに選べる形で閲覧履歴も含めた。

## Consequences

- 「同意した後から記録する」という前提が、「同意した時点で過去30日分も読む」に変わる。初回の説明画面でそのことを明示する。
- 管理者権限が要る元（SRUM、セキュリティのイベントログ）を読むかどうかは、インストーラーが管理者権限で動くかに左右される。社員本人がインストールする前提（`docs/product-overview.md`）と両立するかは未確認。
- 閲覧履歴のファイルはブラウザ使用中は開けないことがあるので、写しを取って読む。
- MVP で「作らない」としていたファイル操作の把握のうち、過去分のファイル記録（記号化したもの）だけは読むことになる。記録分でファイル操作を監視しないことは変わらない。
