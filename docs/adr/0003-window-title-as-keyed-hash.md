# ウィンドウタイトルは読めない記号と拡張子だけを残す

MVP では、ウィンドウタイトルを生の文字列で保存せず、PC 内にだけある鍵を使ったハッシュ（HMAC 等）に置き換え、ファイルの拡張子（`.xlsx` など）が読み取れればそれだけを別に残す。同じ題名は同じ記号になるので、「毎回同じファイルや画面で作業している」ことは Analyst 側で分かる。一方、題名には顧客名や案件名が入りうるので、読める形では残さない。鍵を Client PC の外に出さないのは、鍵なしのハッシュだと、顧客名の候補を片端から試して元の題名を当てられるためである。

## Considered Options

- 一切残さない（アプリ名だけ）: 最も安全だが、同じアプリの中で違う作業を見分けられない。
- 数字などを伏せて読める形で残す: 分析はしやすいが、顧客名を伏せる規則を漏れなく作れる保証が無い。

## Consequences

- 鍵は Diagnostic Export に含めない。コンサルタントは題名の中身を知らないまま分析し、中身は報告会で社員に聞く。
- 鍵を作り直すと記号が変わるので、書き出しの期間の途中で鍵を変えない。
- この粒度で業務を見分けられるかは、実データで確かめるまで分からない。足りなければ、この ADR を見直す。
