# #3 Spec: FlowLens Collector MVP（Past Import + Live Capture + Diagnostic Export）

## Problem Statement

コンサルタントは、お客様に「何を自動化したいですか」と聞いても、ヒアリングで出てこない業務や、声の大きい人に偏った候補しか集められない。実際の PC 操作から繰り返しの仕事を見つけたいが、既存の記録ツール（DeskMate など）は入力内容・Clipboard 本文・画面を保存し、AI や外部通信を含むため、情報管理の厳しい会社には持ち込めない。また、記録を始めてから約30日待たないと最初の提案ができず、商談の勢いが落ちる。

社員の立場では、監視されているようで不安があり、何が残るのか、いつ止められるのかが分からないツールは入れたくない。

## Solution

Client PC に入れる Collector を作る。社員が自分でインストールし、初回の説明に同意すると、次の2つが動く。

1. **Past Import**: Windows や各アプリが既に残している過去30日分の足跡を、その場で読み込む。読む元は社員が選べる。
2. **Live Capture**: その時点から先の App Session、Operation Type、Typing Activity、Clipboard Transfer、Control Metadata を記録し続ける。

どちらも User Content を保存しない（ADR 0002）。ウィンドウタイトルとファイル名は PC 内の鍵を使ったハッシュと拡張子にする（ADR 0003）。社員は常駐アイコンで記録中かどうかを確かめ、一時停止、除外アプリの指定、データの削除ができる。「診断データを書き出す」を押すと、期間を選び、パスワードを付けて AES-256 で暗号化した Diagnostic Export を1ファイルで手元に保存できる。Collector は AI を含まず（ADR 0001）、外部と通信しない。

コンサルタントは、そのファイルを別の PC で 7-Zip で開き、手順書に沿って Claude Code で分析する。過去分を使えば、入れてから数日で最初の提案ができる。

## User Stories

### インストールと初回

1. As a 社員, I want インストーラーを実行するだけで Collector が入ること, so that Python などの準備をしなくて済む
2. As a 社員, I want 初回に、目的・PC 内に保存されること・AI も外部送信も無いこと・文字や本文は残らないこと・いつでも止められることの説明を見ること, so that 何が起きるかを理解してから同意できる
3. As a 社員, I want 同意するまで記録も読み込みも始まらないこと, so that 知らないうちに記録されない
4. As a 社員, I want 初回の説明で、過去30日分も読み込むことと、読み込む元の一覧・それぞれから何を読むかを見ること, so that 過去分について納得して同意できる
5. As a 社員, I want 読み込む元ごとに外せること, so that 読まれたくない元（閲覧履歴など）を除ける
6. As a 社員, I want 初期状態ではすべての元が選ばれていること, so that 特に考えなければ最大限の情報でコンサルタントの提案が早くなる
7. As a 社員, I want スタートメニューから Collector を開けること, so that 後から設定や状態を確認できる

### Past Import

8. As a コンサルタント, I want 入れた直後に過去30日分の足跡が読み込まれること, so that 「3日後にご提案します」と言える
9. As a コンサルタント, I want 過去分からアプリごと・時間帯ごとの使用時間が分かること, so that どのアプリに時間を使っているかを最初の提案で示せる
10. As a コンサルタント, I want 過去分から PC を使っていた時間帯（起動・終了・スリープ・復帰・ログオン・ロック）が分かること, so that 業務時間の外を業務と誤認しない
11. As a コンサルタント, I want 過去分から開いたファイルの記号・拡張子・時刻・開いたアプリが分かること, so that 同じファイルを繰り返し開く業務を見つけられる
12. As a コンサルタント, I want 過去分から訪れたサイトのドメインと時刻が分かること, so that ブラウザで行う業務の目星を付けられる
13. As a 社員, I want 過去分でも、本文・入力内容・URL のクエリ・ファイル名や題名の生の文字列が保存されないこと, so that 過去の仕事の中身が漏れない
14. As a 社員, I want 読み込みの進み具合と、元ごとに読めた件数・読めなかった理由が表示されること, so that 何が読まれたかを確かめられる
15. As a 社員, I want 初回に外した元を後から追加で読み込めること, so that 気が変わっても入れ直さずに済む
16. As a コンサルタント, I want 過去分と記録分が区別されて保存されていること, so that 粒度の違うデータを混ぜて数えない
17. As a 社員, I want 管理者権限が無くて読めない元があっても、残りの元は読み込まれること, so that 1つの失敗で全体が止まらない
18. As a 社員, I want 除外アプリに指定したアプリの過去分も除かれること, so that 除外の設定が過去分にも効く
19. As a 社員, I want ブラウザを使っている最中でも閲覧履歴を読み込めること, so that ブラウザを閉じる手間が要らない

### Live Capture

20. As a 社員, I want ログインすると自動で記録が始まること, so that 毎回起動しなくて済む
21. As a 社員, I want Collector が二重に起動しないこと, so that 記録が重複しない
22. As a コンサルタント, I want 前面にあったアプリと、その開始・終了の時刻（App Session）が記録されること, so that アプリの移り変わりと時間が分かる
23. As a コンサルタント, I want 操作していない時間・ロック中・スリープ中・セッション切断中が App Session に含まれないこと, so that 離席を作業時間と誤認しない
24. As a コンサルタント, I want ウィンドウタイトルが記号と拡張子で記録されること, so that 同じファイルや画面での作業の繰り返しを見分けられる
25. As a 社員, I want ウィンドウタイトルの生の文字列が保存されないこと, so that 顧客名や案件名が残らない
26. As a コンサルタント, I want クリック・フォーカスした UI 部品の種別と識別情報（Control Metadata）が記録されること, so that 「Excel で保存ボタンを押した」のような流れが分かる
27. As a 社員, I want UI 部品に表示・入力された内容が保存されないこと, so that 画面の中身が残らない
28. As a コンサルタント, I want Ctrl+C / X / V、Enter、Tab、Escape、ショートカットの起動が Operation Type として記録されること, so that 定型操作の流れが分かる
29. As a コンサルタント, I want 入力の回数と継続時間（Typing Activity）がウィンドウごとに記録されること, so that 手入力の多い作業が分かる
30. As a 社員, I want 入力した文字・文章・IME の確定内容が保存されないこと, so that 何を書いたかが残らない
31. As a コンサルタント, I want Copy / Cut と Paste の組（Clipboard Transfer）が、元のアプリ・先のアプリ・種類・長さつきで記録されること, so that アプリ間の転記作業を見つけられる
32. As a 社員, I want Clipboard の中身が保存されないこと, so that コピーした内容が残らない
33. As a 社員, I want パスワード欄での入力は回数も含めて何も記録されず、そうした時間があったことだけが残ること, so that パスワードに関わる情報が一切残らない
34. As a コンサルタント, I want ブラウザでの作業はドメインまで記録されること, so that どのサイトで作業しているかが分かる
35. As a 社員, I want URL のパス以降・クエリ・フラグメント・トークンが保存されないこと, so that 個別の画面やセッション情報が残らない
36. As a 社員, I want 強制終了・スリープ・再起動・Windows Update のあとも自動で記録が再開されること, so that 放っておくだけで済む

### 常駐アイコンと状態

37. As a 社員, I want 画面右下のアイコンで記録中か一時停止中かがいつでも分かること, so that 隠れて記録されていないと確かめられる
38. As a 社員, I want アイコンから一時停止と再開ができること, so that 見られたくない時間を記録から外せる
39. As a 社員, I want 状態の画面で、記録中か・収集開始日・記録済み時間・データ使用量が見えること, so that どれだけ記録されたか分かる
40. As a 社員, I want 記録しないアプリを指定できること, so that 私用のアプリなどを除ける
41. As a コンサルタント, I want 除外アプリが前面の間は「除外中だった時間」だけが残ること, so that 時間の空白の理由が分かる
42. As a 社員, I want 除外アプリでの操作・Clipboard・URL がどれも記録されないこと, so that 除外の設定が確実に効く

### データの削除と保存期間

43. As a 社員, I want 記録データを「今日／過去7日／過去30日／すべて」で削除できること, so that 自分の記録を自分で消せる
44. As a 社員, I want 削除の前に確認が出ること, so that 誤って消さない
45. As a 社員, I want 保存期間（初期値30日）を過ぎた記録が自動で消えること, so that データが増え続けない
46. As a 社員, I want 保存期間を 30／60／90日／無期限から選べること, so that 観測期間に合わせられる

### Diagnostic Export

47. As a 社員, I want 「診断データを書き出す」ボタン1つで書き出しを始められること, so that 迷わず渡せる
48. As a 社員, I want 期間を過去7日／14日／30日／すべて／日付指定から選べること, so that 必要な分だけ渡せる
49. As a 社員, I want 書き出す前に、除外アプリの記録・URL の無害化・不要な項目の削除がもう一度行われること, so that 保存時に漏れたものも外に出ない
50. As a 社員, I want 書き出すファイルにパスワードを付けて AES-256 で暗号化できること, so that メール添付などで第三者のサーバーを通っても読まれない
51. As a 社員, I want 書き出したファイルが手元に1つ保存されるだけであること, so that 渡し方を自分で選べる
52. As a コンサルタント, I want ファイルに データ本体（SQLite）・`manifest.json`・`summary.json`・`redaction_report.json`・`README.txt` が入っていること, so that 開いてすぐ分析に取りかかれる
53. As a コンサルタント, I want `manifest.json` に版・期間・件数・ランダムな機器 ID が入っていること, so that どの PC のどの期間か分かる
54. As a 社員, I want 機器 ID に PC 名やユーザー名が使われないこと, so that 誰の PC か特定されない
55. As a コンサルタント, I want `summary.json` にアプリごとの時間とアプリ間の転記回数が入っていること, so that 最初の見立てをすぐ立てられる
56. As a コンサルタント, I want `redaction_report.json` に除外したものの件数だけが入っていること, so that 無害化が効いたか確かめられる
57. As a 社員, I want 題名の記号を作る鍵がファイルに含まれないこと, so that コンサルタントにも題名の中身が分からない

### Analyst 側

58. As a コンサルタント, I want 7-Zip でファイルを開く手順書があること, so that 開発者本人がいなくても分析を始められる
59. As a コンサルタント, I want データの読み方と Claude Code への渡し方の手順書があること, so that 同じ手順で分析を再現できる
60. As a コンサルタント, I want 過去分と記録分の違いが手順書に書かれていること, so that 粒度の違いを踏まえて分析できる

### 通信なしとアンインストール

61. As a お客様の情報管理担当者, I want Collector が外部と一切通信しないこと, so that 導入の許可を出せる
62. As a 社員, I want アンインストールできること, so that 観測が終わったら元に戻せる
63. As a 社員, I want アンインストール時に記録データを消すか残すかを選べること, so that 書き出し前のデータを誤って失わない
64. As a 開発者, I want 障害調査用のログに業務データや入力内容が書かれないこと, so that ログから情報が漏れない

## Implementation Decisions

- **構成**: Collector は、Windows とやり取りする薄い「観測の入口」群と、それ以外すべてを担う「記録の中核」に分ける。
  - 観測の入口（Live Capture 用）: 前面ウィンドウの切り替え、idle、ロック・スリープ・切断、キーボード、マウス、UI Automation、Clipboard、ブラウザのアドレス。DeskMate の `win_events` 等を小さく流用する（`docs/research/deskmate-survey.md` の5分類に従う）。
  - 観測の入口（Past Import 用）: システムのイベントログ、セキュリティのイベントログ、SRUM、UserAssist、最近使ったファイル・ジャンプリスト、Office の最近使ったファイル、Chrome / Edge の閲覧履歴。すべて新規。
  - 入口は、生の文字列を含みうる「観測」を中核へ渡すだけで、判断をしない。無害化・除外・記号化・保存・集計・書き出しは、すべて中核で行う。
- **記録の中核の外向きの顔**: 観測を受け取る口、設定（除外アプリ、保存期間、一時停止、読み込む元の選択）を受け取る口、削除の口、書き出しの口（期間・パスワード → 1ファイル）。自動テストはこの顔だけを使う。
- **無害化**: 中核が観測を受け取った時点で、本文になりうる項目を捨て、ウィンドウタイトルとファイル名を鍵付きハッシュ（HMAC 等）と拡張子にし、URL をドメインにする（ADR 0002、0003）。書き出し時にもう一度同じ規則をかける。鍵は Client PC 内に置き、書き出しに含めない。書き出し期間の途中で鍵を変えない。
- **保存**: SQLite（WAL）。DeskMate のスキーマは流用せず小さく作り直す。App Session、Activity Event（Operation Type・Control Metadata を含む）、Typing Activity、Clipboard Transfer、除外中だった時間、Past Import の記録、除外設定、書き出し履歴、スキーマの版を持つ。すべての記録に「過去分か記録分か」と「読み込んだ元」を持たせる。本文の列は持たない。自動削除はすべての記録のテーブルを対象にする。
- **Past Import の動き**: 同意の直後に、選ばれた元を順に読む。元ごとに独立して失敗してよく、読めた件数と読めなかった理由を残す。後から外した元を追加で読める。ブラウザの閲覧履歴は写しを取って読む。管理者権限が要る元の扱いはインストーラーの権限次第（下記 Further Notes）。
- **書き出し**: 期間を選び、再無害化し、SQLite・`manifest.json`・`summary.json`・`redaction_report.json`・`README.txt` をまとめ、実績のある部品で AES-256 の ZIP にする。独自の暗号方式は使わない。`summary.json` は AI を使わず集計で作る。
- **常駐と画面**: ユーザーのセッション内で動く常駐アプリとする（Windows Service にはしない）。常駐アイコン、初回の説明画面（読み込む元の選択を含む）、状態の画面、除外設定、削除、書き出しの画面を持つ。
- **配布**: Python 不要の1つの実行ファイルとインストーラー。まとめ方（PyInstaller、Nuitka、Inno Setup、WiX 等）は依存を確かめて選ぶ。
- **通信**: 通信する部品（REST、AI、更新確認、利用状況の送信）を持ち込まない。

## Testing Decisions

- **良いテストとは**: 記録の中核の外向きの顔だけを通して、外から見える結果を確かめるもの。中身の関数や表の構造は確かめない。作り替えても、振る舞いが同じならテストは直さずに済むこと。
- **テストの当て所（1か所）**: 偽の観測（偽の操作、偽の過去記録）を中核に流し込み、書き出した1ファイルを開いて中身を確かめる。利用者と合意した「入口と出口の1か所」。
  - 例: 「Chrome → Excel → Outlook」の偽の操作を流すと、その順の App Session が正しい時間で入っている。
  - 例: 途中に5分の idle とロックを挟むと、その時間が App Session に含まれない。
  - 例: 本文・パスワード欄の入力・Clipboard 本文・題名の生の文字列・URL のクエリを含む偽の観測を流しても、書き出したファイルのどこにもその文字列が現れない（ファイル全体を文字列で検索する）。
  - 例: 除外アプリの観測は、除外中だった時間以外何も残らない。過去分にも効く。
  - 例: 過去分の偽の記録は、過去分として区別されて入る。1つの元が失敗しても他の元は入る。
  - 例: 30日分を書き出すと1ファイルになり、パスワードで開け、中の SQLite に問い合わせできる。
  - 例: 保存期間を過ぎた記録は自動で消える。削除の範囲どおりに消える。
- **テストしないもの（実機で手順書どおりに確かめる）**: Windows とやり取りする観測の入口そのもの（フックが呼ばれるか、SRUM が読めるか等）、インストーラー、常駐アイコン、アンインストール。確認手順は手順書として残す。
- **通信なしの確認**: Collector の依存に通信する部品が無いことと、記録・書き出しの間に外へ接続しないことを、テストで確かめる。
- **先行例**: まだコードが無いので、このリポジトリに先行例は無い。DeskMate のテスト（Linux 上で18件が通った）は、偽の入力を中核に流す形の参考にする。

## Out of Scope

- 画面の撮影と文字の読み取り（処理そのものを持たない）
- ブラウザの拡張機能
- これから先のファイル操作の監視（過去分のファイル記録は Past Import で読む）
- Analyst 側のプログラム（Operation Sequence の集計、Workflow Candidate の発見、レポート作成）。MVP は手順書だけ
- Client PC での AI、外部通信、自動送信、遠隔操作
- 人を評価する機能、組織単位の管理画面、管理者による一括配布や記録停止の禁止
- 業務の自動実行（RPA）

- **未確認の危険2**: 題名を記号にした粒度で業務を見分けられるかは、実データで確かめるまで分からない（ADR 0003）。
- **未確認の危険3**: UI 部品の Name から、固定のラベルとユーザーが書いた内容を見分けられるかは未調査。見分けられなければ MVP では保存しない（ADR 0002）。
