  - 中身を読まないクリップボードの監視

  - 説明・同意画面、読み込みの進み具合、状態画面、設定・削除・書き出し画面
- **配布**: PyInstaller の設定と Inno Setup のスクリプト（`installer/`）。管理者権限は要らない。自動起動、強制終了後の再起動タスク、アンインストール時にデータを残すか選ぶ画面を含む。
- **文書**: `docs/consultant-guide.md`（コンサルタント向け）、`docs/manual-checks.md`（実機確認の手順）。

## 試験の結果

- `python -m pytest`: 60件すべて合格（Linux, Python 3.12）。`python -m ruff check .`: 指摘なし。
- 試験は、偽の観測を中核に流し、書き出したファイルを**パスワードで開いて**、中身をすべての同梱ファイルにわたって文字列検索する形で行う。題名・入力文字・コピー内容・URL の続き・PC 名・ユーザー名・鍵が出ないことを確かめている。
- 閲覧履歴の読み取りだけは Windows 側の部品だが、SQLite だけで動くため、偽のプロファイルで直接試験している（URL の続きが Python 側に渡らないこと）。
- Windows 側の残りは、Windows 用の部品を偽物に差し替えて Linux で通しで動かし、配線の誤り（引数名の違い、存在しない関数の呼び出し）が無いことだけを確かめた。**実機では一度も動かしていない。**

## 残っている課題

- **Windows 実機での確認がまだ。** `docs/manual-checks.md` の全項目が未実施。特に次の点は、実機でないと分からない。
  - uiautomation の各呼び出し
  - アドレスバーの識別（`OmniboxViewViews`）
  - タスクトレイのメニュー
  - イベントログの時刻の扱い
  - taskkill で正常に閉じられるか
- **配布物はまだ作っていない**（PyInstaller と Inno Setup は Windows 上で動かす必要がある）。
- **過去分で「1時間ごとのアプリ使用時間」は取れない。** SRUM は管理者権限と専用の部品が要るため読まない（ADR 0004）。アプリの利用回数は、PC に入ってからの累計で代用している。
- **セキュリティの記録（ロック・解除）は、社員の権限では読めない。** 読み込み結果に「読めず」と出る。
- **強制終了後の再起動は最大10分遅れる。** タスク スケジューラで10分ごとに確かめる方式のため。会社の設定でタスクを作れない場合は、次のサインインまで止まる。
- **Paste の検出は Ctrl+V だけ。** 右クリックの「貼り付け」は、貼り付け先の分からないコピーとして残る。

## プライバシー上の残りのリスク

- **アドレスバーの読み取り。** Chrome/Edge のアドレスバーに限って、ページが変わるたびに値を読み、その場でホスト名に縮めている（ADR 0002 補足）。一瞬とはいえ、メモリ上には URL 全体が載る。
- **クリップボードの長さ。** パスワード管理アプリはあらかじめ除外しているが、それ以外のアプリからパスワードをコピーした場合、その長さは残る。
- **UI 部品の識別情報。** 形で選んではいる（英数字のみ・空白なし）ものの、Web 画面が識別情報に短い英数字の内容を入れていれば、それは残りうる。
- **題名の記号**は16文字（64ビット）で、鍵が無ければ元に戻せない。一方で「同じ題名かどうか」は分かる。
