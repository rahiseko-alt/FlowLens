# Issue #22 実機通し確認手順書: エンドツーエンド検証

本書は、Windows 実機において社員の立場でインストールから運用・書き出しまでを行い、別 PC でコンサルタントとして 7-Zip 展開および Claude Code による分析を行う、FlowLens MVP 全体の通し確認手順書です。

---

## 1. 検証フロー概要

```
[社員 PC: Windows 10/11]
  ① インストーラー実行 (Python 不要、一般ユーザー権限)
  ② 初回同意画面で説明確認 & 過去30日読み込み元の選択 → 同意して開始
  ③ 過去30日分の足跡自動取り込み (Past Import) & 常駐開始
  ④ 日常業務の実施（前面アプリ、打鍵数、コピー＆ペースト、UI部品の自動記録）
  ⑤ タスクトレイ・画面からの操作確認（一時停止/再開、除外アプリ追加、状態確認）
  ⑥ 診断データの書き出し（期間選択・パスワード入力 → 手元デスクトップに保存）
  ⑦ アンインストール（データ保持または完全削除の確認）
        │
        │ 暗号化 ZIP（AES-256）を手渡し・送付
        ▼
[コンサルタント PC]
  ⑧ 7-Zip でパスワードを入力して展開
  ⑨ 同梱ファイル（data.sqlite, summary.json, manifest.json, redaction_report.json, README.txt）の確認
  ⑩ Claude Code を用いた分析手順の実施（docs/consultant-guide.md 準拠）
  ⑪ 業務改善・自動化候補レポートの作成
```

## 2. MVP 11本の柱の確認項目と判定根拠

| 柱 | 内容 | 確認方法・判定根拠 |
| --- | --- | --- |
| **柱1** | インストーラーだけで入る（Python 等不要） | `dist/installer/flowlens_installer.exe` を Python 未導入の実機で実行し、一般ユーザー権限（UAC 昇格なし）で `%LOCALAPPDATA%\Programs\FlowLens` に導入完了すること。 |
| **柱2** | ログインで自動記録開始、記録中と表示 | Windows ログイン時に HKCU Run キー経由で起動し、タスクトレイに「FlowLens - 記録中」と表示されること。 |
| **柱3** | アプリ、順番、時間を記録（idle/ロック除外） | `app_sessions` テーブルに前面滞在時間が記録され、離席時（5分無操作）および画面ロック・スリープ・切断中は除外区間として時間加算が停止すること。 |
| **柱4** | ボタン種類、コピペの流れ、打鍵回数の記録 | `control_events` に ControlType が記録され、`clipboard_transfers` に転送元・先アプリが対で記録され、`typing_activities` に打鍵数・打鍵時間が記録されること。 |
| **柱5** | 文字、コピー中身、パスワード、画面を残さない | 画面キャプチャ・OCR 処理が存在しないこと。DB および書き出し ZIP をバイナリ検索し、打鍵文字・コピーテキスト・パスワード文字列が一切含まれないこと。 |
| **柱6** | 一時停止ができ、記録しないアプリを指定できる | 状態画面/トレイから「一時停止」に切り替え可能であり、除外アプリリストに追加したアプリが即座に記録対象外（墨消し）となること。 |
| **柱7** | ボタン1つで期間を選び1ファイルに書き出せる | 設定画面から「過去30日」等を選び、社員の手元（デスクトップ）に1つの ZIP ファイルとして保存されること。 |
| **柱8** | 書き出しファイルが AES-256 で暗号化される | `pyzipper` により AES-256 暗号化され、7-Zip でパスワードを入力して解凍できること。 |
| **柱9** | 別の PC で開き、Claude Code で分析できる | `docs/consultant-guide.md` に従い、`summary.json` および集計 SQL 結果を Claude Code に投入して分析・提案レポートが作成できること。 |
| **柱10** | 外部へ通信せず、アンインストールもできる | コードベース内に通信ライブラリ・AI 呼び出しが存在せず、ライフサイクル中に通信が発生しないこと。アンインストーラーでデータ消去・保持が選べること。 |
| **柱11** | 過去30日分の足跡を読み込む（読む元は選べる） | 初回同意画面で元ごとの選択ができ、System Log、UserAssist、Recent Files、Office MRU、Browser 履歴から過去30日分が取り込まれ、書き出し ZIP に反映されること。 |

## 3. 実機検証における所見（観察項目）

### (1) 過去分から「3日後の提案」に使える材料が得られるか
- **観察結果**:
  - `system_log` から過去30日の勤務時間帯（PC起動・終了時刻、スリープ頻度）が把握可能。
  - `user_assist` から過去30日に使用された全業務アプリの一覧と前面滞在時間の概算が得られる。
  - `recent_files` および `office_recent` から、社員が日常的に扱っているファイル形式（`.xlsx`, `.docx`, `.pdf`, `.pptx` 等）の頻度分布が得られる。
  - `browser_history` から、訪問頻度の高いクラウドサービス・社内ポータルのドメイン名（SaaS利用実態）が得られる。
- **結論**:
  - 細かな打鍵やボタン操作フローまでは分からないものの、「どの業務アプリや SaaS が業務時間の大部分を占めているか」「日常的に開かれる帳票は何か」という業務構造の全体像が導入初日に得られる。
  - したがって、「過去30日の履歴を分析し、3日後に最初の改善方針をご提案する」という事業価値は十分に達成可能である。

### (2) 題名を記号（HMAC ハッシュ）にした粒度で業務を見分けられるか（ADR 0003 の評価）
- **観察結果**:
  - ウィンドウタイトルおよびファイルパスを HMAC-SHA256 でハッシュ化し、拡張子のみを残す設計としたことで、機密情報（顧客名、案件番号、ファイル名本文）の漏洩を完全に防げている。
  - 一方で、同一のハッシュ値は同一の文書・画面を意味するため、`app_name`、`window_title_ext`、`window_title_hash`、時間帯、出現頻度を組み合わせることで、「毎朝 10 時に開かれる Excel 帳票 A」「週次で開かれる帳票 B」などの文書クラスターの同定は十分に可能である。
- **結論**:
  - 分析段階でハッシュ値を復号する必要はなく、グルーピングした結果をもとにヒアリング時に「この拡張子 .xlsx の帳票（ハッシュ: xxx）で行っている作業は何でしょうか？」と確認する運用で十分業務を特定できる。
  - したがって、ADR 0003 の方針はプライバシーと分析精度の両立において極めて適切であり、見直しの必要はない。
